# Project decisions

All rows were confirmed by the user during inception (2026-11-13). Tags: [O] Omarchy does it, [C] CachyOS does it, [New] neither does. Component-level picks are in `docs/components.md`, the keybindings in `docs/keybindings.md`, and the menu tree in `docs/menu.md`. Those three docs are binding too.

## Binding decisions

| D-01 | Name: **karchy**. The old Nulifyer/karchy Go launcher repo gets renamed to `karchy-launcher` and archived, then a fresh Nulifyer/karchy is created. GitHub changes need the user's approval at the time. | User doesn't want the old launcher | Inception round, last round |

| D-04 | Kernel: `linux-cachyos` + `linux-cachyos-nvidia-open` on NVIDIA machines, with Arch `linux-lts` as the fallback entry [C] | Newest stable kernel fastest (7.3.3 vs Arch 7.2.15 on 2026-11-13) | `pacman -Si` comparison |

| D-63 | **VMs and containers: karchy's own panels, no libvirt.** Two shell plugins, each a bar icon that shows when something runs (so a background VM or container is never forgotten), a panel for quick control of what's running, and a full window for everything. **VMs (`karchy.vms`)**: `karchy vm` runs QEMU/KVM directly: a VM is a folder in `~/VMs/<name>/` (`vm.conf`, disk image, UEFI vars, TPM state); it runs headless with SPICE and QMP on unix sockets in `$XDG_RUNTIME_DIR/karchy-vm/`, "Open" shows it with `spicy` (spice-gtk; virt-viewer would pull in libvirt), stop is an ACPI power-off over QMP. **Containers (`karchy.containers`)**: rootless Podman with the `docker` alias (podman-docker) and Compose against Podman's socket; the panel reads `podman ps --format json` and groups Compose projects; Docker CLI works the same when Docker is the engine. As built: VMs run as transient `systemd --user` units (`karchy-vm-<name>.service`) whose `ExecStopPost` tells the shell, so the bar updates without polling; the ISO is picked through the desktop portal; the Windows profile has TPM and Secure Boot firmware, which starts in Setup Mode (no keys enrolled). Containers: `podman.socket` enabled for all users (`--global`, no user file edits, D-23); `DOCKER_HOST` set by the feature in `/etc/environment.d` (not shipped by karchy-settings, since a fixed value would break a real Docker setup); nvidia-container-toolkit's own `nvidia-cdi-refresh` units regenerate the GPU spec, so karchy needs no hook.
