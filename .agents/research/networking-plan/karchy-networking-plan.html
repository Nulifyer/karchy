karchy Networking Plan

How Wi-Fi, VPN, DNS and the firewall fit together, who owns each part, how it's maintained, and the order it gets built. Plus the rule for what is core, a package or a plugin.

In short

One idea drives everything: “trusted network”

You mark home as trusted once. That one switch decides three things: LocalSend can receive files, the VPN stands by, and the router's DNS is used (so nas.lan works). Everywhere else: VPN on, your encrypted DNS, LocalSend closed.

Trust follows the router, not the name

Today trusting “Wired connection 1” trusts every Ethernet jack you ever plug into. Trust will record your router's hardware address, so a hotel cable or a fake “Home-5G” is never trusted.

The VPN becomes part of the network panel

One icon, one panel. The VPN's system half becomes a pacman package built from its own repo; its controls (Off / Auto / On) live in the network panel. Your plugin repo keeps working on stock Omarchy.

Café sign-in works with the VPN on

“Sign in to network” pauses the VPN's block for up to 5 minutes, opens the sign-in page, and turns protection back on by itself once you're online.

Core, package or plugin Green light

Four questions, asked in order. The first yes decides. This applies to everything in karchy, not just networking.

1 · Does it run as root, or ship system files?

Package. Root code, systemd units, polkit rules, udev rules and anything in /etc or /usr come from a signed pacman package. Never from a plugin cloned with git (the rule that root never runs code your user can edit).

2 · Does every karchy machine need it, or do other core parts depend on it?

Core, inside the karchy package. The bar, menu, Settings, panels, theme engine and commands.

3 · Only some machines (hardware) or opt-in (a feature)?

Package in a tier: detected at install or offered in Settings. Its screen stays in core and hides until the package is installed, as Containers and VMs do today. One release, no plugin to keep in step.

4 · User-level UI only, optional, maybe for Omarchy too or from someone else?

Plugin (karchy plugin add). Runs as you, lives in its own repo, can't touch the system. If it ever needs root, its system half becomes a package (question 1).

What happens where

At home (trusted)

  • VPN in Auto stands by
  • DNS from your router, so nas.lan and printers resolve
  • LocalSend can receive
  • Panel: “Connected · Trusted network”

At a café

  • Join Wi-Fi; panel shows “Sign in to this network”
  • Click: VPN block paused, sign-in page opens
  • Once online: VPN connects, protection back, page closes
  • DNS: your encrypted DNS until the VPN is up, then the VPN's

The VPN can't connect

  • Internet stays blocked (no leak)
  • Panel says so in words, with “Retry” and “Use without VPN”
  • “Use without VPN” switches the mode to Off and says it did

Hotel Ethernet

  • Same profile as home, different router
  • Not trusted, so VPN on and LocalSend closed
  • Settings shows “Trusted, but a different router: not trusted now”

On a plane

  • Airplane key or panel: all radios off
  • Panel and an on-screen message say “Airplane mode”

Desktop, wired only

  • No Wi-Fi list or switch shown
  • Ethernet, VPN row and details only

The contract between karchy and the VPN package

Four promises, written down in both repos. Either side can change its insides freely as long as these hold.

Trust: karchy writes, VPN reads

The VPN reads karchy's trusted list (network ID plus router address) and keeps no list of its own.

Status: VPN writes, karchy reads

One JSON file in /run/nulifyer-vpn/ with mode and state (standing by, connecting, protecting, failed, paused). The panel reacts to changes; nothing polls.

Commands: karchy calls, VPN acts

nulifyer-vpn mode off|auto|on and nulifyer-vpn portal-pause, allowed for your user without a password by the package's polkit rule.

DNS: each in its lane

The VPN sets DNS only on its tunnel; karchy sets it only on untrusted Wi-Fi and Ethernet. Neither edits saved networks.

Settings › Network

  • Status: one card per active connection (IP, gateway, DNS in use, speed, band)
  • Saved networks: each opens in place: trusted, connect automatically, metered, band, private address, IP settings, share, forget
  • DNS: Automatic, Quad9, Cloudflare or custom; encrypted DNS; “use on trusted networks too” (off)
  • VPN: import a WireGuard file, default mode, block internet while connecting, allow local devices on trusted networks
  • Sharing and firewall: what's open right now (read-only)
  • Advanced: Wi-Fi country, connectivity check

Not now: hotspot, proxy, Bluetooth tethering.

The bar shows one network icon. It gets a VPN variant while protected and turns to the warning or error color while the VPN connects or has failed, so a blocked internet is never hidden. The rotating “Bending light” phrases go; the status line says the real state.

Build order

Step 1
Decided
Quick fixes, all small. One .local answerer; network tuning; LocalSend's port closed at boot until a trusted network connects (today it stays open after a reboot); the password prompt says what really failed and keeps it on screen; Wi-Fi hardware switch shown; trust prompt reads in words and Cancel isn't an error; sign-in button opens http://neverssl.com; work/school Wi-Fi checks the server's certificate.
Step 2
Fix
Honest panel details. With the VPN up, the panel shows your real Wi-Fi or Ethernet plus a separate VPN line (today it shows the tunnel labelled “Ethernet” and hides the QR button).
Step 3
Decided
One trusted list, bound to the router. Changes the trust file once; the VPN reads it. Settings flags “different router”.
Step 4
Decided
VPN package. Package the VPN's system half, add the status file, the commands and the portal pause, drop dnscrypt-proxy, allow local devices on trusted networks. Done in your VPN repo, then packaged here.
