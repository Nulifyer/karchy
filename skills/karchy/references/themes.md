# Themes, backgrounds and fonts

A theme switch, a background or a font is a small change. Make it, then tell the user the previous value so they can switch back. Get the previous value first: `cat ~/.local/state/karchy/current/theme.name` and `karchy font current`.

## Commands

| Task | Command |
| --- | --- |
| List themes | `karchy theme list` |
| Apply a theme | `karchy theme set "<name>"` |
| Install a theme from a git repository | `karchy theme install <git url>` |
| Remove a user theme | `karchy theme remove "<name>"` |
| List the themes that came from a git clone | `karchy theme extras` |
| Apply the current theme again after its files changed | `karchy theme refresh` |
| Set a background image or video | `karchy theme bg set <path>` |
| Next background of the current theme | `karchy theme bg next` |
| List, show, set the monospace font | `karchy font list`, `karchy font current`, `karchy font set "<name>"` |
| Text size everywhere (shell, GTK, terminals) | `karchy display text size [9-20\|reset]` |

The bar's look (position, background, style) is `karchy bar`. See [hyprland.md](hyprland.md).

## Where themes live

- Packaged themes: `/usr/share/karchy/themes/<name>`. Read only.
- The user's themes: `~/.config/karchy/themes/<name>`. If a user theme has the name of a packaged theme, its files are laid over the packaged theme's files. Use a new name unless the user wants that.
- The applied theme: `~/.local/state/karchy/current/theme`, generated by `karchy theme set`. Do not edit it. The next theme switch replaces it.
- Extra backgrounds for one theme: `~/.config/karchy/backgrounds/<theme name>/`. `karchy theme bg next` cycles through these and the theme's own.

## Make or change a theme

A theme is a folder with `colors.toml` and a `backgrounds/` folder. Everything else is generated from `colors.toml` through the templates in `/usr/share/karchy/default/themed`. Optional files, such as `preview.png` or `vscode.json`, are in the packaged themes for reference.

1. Copy a packaged theme to `~/.config/karchy/themes/<new-name>`.
2. Edit `colors.toml` and the backgrounds.
3. Run `karchy theme set "<new-name>"`.

To change the colors of one app only, put a template of the same name in `~/.config/karchy/themed/`. It is used in place of the packaged template. Copy the packaged one from `/usr/share/karchy/default/themed` as the start, then run `karchy theme refresh`.

To change the shell's look without a new theme, write the keys in `~/.config/karchy/shell.toml`. It is laid over the theme and survives a theme switch. The sections and keys are those of `/usr/share/karchy/default/themed/shell.toml.tpl`.

## Traps

- A theme switch never rewrites the user's dotfiles. The starter terminal configs include generated files from `~/.local/state/karchy/current/theme`, and VS Code gets a generated theme. Do not repair a theme by editing a terminal config. If the user changed their terminal config so that it no longer includes the theme file, that is their choice. Tell them, and do not undo it.
- `karchy theme install` runs `git clone`. A theme from a git repository may not ship code: `karchy theme set` ignores its `.lua` files, terminal configs and `vscode.json`, and prints "Ignored in ...". Do not copy those files into place to get around this. Review the repository with the user if they want them.
- `karchy font set` writes `~/.config/fontconfig/conf.d/60-karchy-font.conf` and restarts the shell. The font must be installed first. Check with `karchy font list`. A hand-written `~/.config/fontconfig/fonts.conf` wins over it. The shell's icons use a separate symbols font and do not change.
- The font is the system monospace font. Terminals ask fontconfig for `monospace`. Do not write a font name into a terminal config.
- Chromium-based browsers read the theme color from a system policy. `karchy theme set` writes it through a fixed sudo rule that accepts one color value. This is expected and needs no action.
- A theme switch runs the `theme-set` hook, and a font change runs `font-set` ([layout.md](layout.md)). Use those hooks when the user wants an app of their own to follow the theme.
- `karchy display text size` never edits the user's terminal configs. It writes the terminals' size to karchy's files in `~/.local/state/karchy/terminal/` (`foot.ini`, `kitty.conf`, `ghostty.conf`, `alacritty.toml`), which the starter configs include. A size line of the user's own after the include wins in foot and kitty, and under `[font]` in Alacritty; in Ghostty the include wins, so the user removes that line to set their own. A terminal config without the include doesn't follow the text size. foot shows a new size in windows opened after its last window closed. `karchy display text size reset` returns the defaults.
