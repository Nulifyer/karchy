# Components

What a karchy install contains. Tags: [O] Omarchy does it, [C] CachyOS does it, [New] neither does. Packages come from Arch unless a repo is named. Anything not listed here is not in the base install.

## System

| Area | Choice | Source |
|---|---|---|
| Repos | `[cachyos]` (generic), then Arch live mirrors, then `[omarchy]` (D-45) | [C] + [O] |
| Kernel | `linux-cachyos`, with `linux-cachyos-lts` as the fallback; NVIDIA machines add both `-nvidia-open` modules and CachyOS's `nvidia-utils` (D-45), or both `-nvidia-580xx` modules and `nvidia-580xx-utils` on Maxwell, Pascal and Volta cards | [C] |
| Disk | LUKS2 (the installer's default; one question offers a plain disk instead, with its warning and with karchy's login screen asking for the password at every boot, D-130), btrfs `zstd:1,noatime`, subvolumes `@ @home @root @srv @cache @log @tmp @swap`, 4 GiB ESP at `/boot` | [O+C] |
| Initramfs | systemd + `sd-encrypt` (which has nothing to do on an install without encryption) | [C] |
| Boot | Limine + limine-snapper-sync. The disk password is asked by Plymouth in karchy's theme: the mark, a password box with a bullet per character, "Wrong password. Try again.", and three small tiles that brighten in turn while the boot or the shutdown is at work (D-122). The boot menu and the installer are text screens in the default theme's colours and karchy's monospace font, and so is the disk-password screen of a boot without the splash (D-121) | [O+C] |
| Snapshots | snapper on `@`: before and after package changes, keep 5, no timeline | [O] |
| Swap | zswap (zstd) + swap file on `@swap` sized to RAM; no zram | [New] |
| /tmp | tmpfs, cap = RAM size, aged out after 10 days | [New] |
| Login | greetd auto-login → uwsm → Hyprland. After logging out, and at boot on an install without disk encryption, greetd shows karchy's login screen: a Quickshell screen in the boot splash's look (the mark, the password box, one line of status, the default theme), with the person's name, a choice between several people, and Suspend, Restart and Shut down. greetd's text greeter takes over when it can't start (D-130). Automatic login is only for an encrypted computer with one person: Settings › Users has the switch ("Log in automatically"), adding a second person turns it off, and from then on the login screen follows the disk password (D-139) | [New] |
| Other internal disks | The installer offers to erase and encrypt each one when the system disk is encrypted: LUKS2 + btrfs at `/mnt/data`, opened at boot by a key file on the encrypted system disk, and by the install password by hand (D-132). | Keyring | oo7 (Secret Service); Brave and VS Code store passwords there. It opens by itself at login and has no prompt of its own (D-142). Where karchy's login screen is how a person gets in (no disk encryption, D-131; an encrypted install with automatic login off or more than one person) the login password opens it through PAM (`pam_oo7` in `karchy-login`), and `passwd` changes the keyring's password with it. Only automatic login (encrypted, one person) uses a random key imported as a systemd credential (D-57); `karchy keyring-key export <file>` saves that key for backups and `import` (or `KARCHY_KEYRING_KEY_FILE` at install) puts it back, so a restored home's keyring opens. `/usr/lib/karchy/keyring-login`, run by the login screen's PAM service, changes a keyring from the key to the password or back at its owner's next login after automatic login was turned off or on. `karchy keyring status` says open, locked or none; `karchy keyring reset` (Settings › Security › Saved passwords) erases a keyring that can't be opened, which is what a password reset by an administrator leaves | [New] |
| sudo / polkit | Shell polkit overlay; per-terminal sudo cache (10 min); fingerprint (lid gate on the laptop) for polkit prompts and the lock screen, never sudo (D-14, CVE-2024-37408) | [O] |
| Firewall | ufw deny incoming (+ rules for Podman as needed) | [O] |
| Network | NetworkManager + wpa_supplicant + systemd-resolved; portals detected with Arch's own check, and "Sign in to network" opens `http://neverssl.com` in a floating window. Tuning in karchy-settings (`/usr/lib`, so files in `/etc` win): Wi-Fi power save off, ARP only for the interface's own address, TCP MTU probing, BBR + fq; avahi is the only `.local` responder (resolved's LLMNR and mDNS off). Trusted networks (D-68): one list, bound to the router's hardware address (and, for Wi-Fi, the name and security), so the same profile behind another router isn't trusted; Settings › Network says "Trusted, but a different router: not trusted now". DNS: on networks that aren't trusted, the live connection uses Quad9 over TLS (`/etc/karchy/dns` changes the provider); trusted networks keep the router's DNS; saved networks are never rewritten, and a VPN's own DNS wins while it is up. The network panel (D-66, D-68) says the real state in its status line (no rotating phrases), shows one attention row only when something needs the person (networking off, airplane mode, the hardware switch, a sign-in page, a failed VPN, DNS blocked) with the action that resolves it, the VPN row, ping, loss, IP and gateway, the band, known and other networks, and "Network settings…", which opens Settings › Network at the connection. | Bluetooth | bluez + shell panel | [O] |
| Printing + scanning | Optional feature (Quick install › System features), D-38 | [O] + [New] |
| Audio | PipeWire + WirePlumber | [O+C] |
| Laptop power | power-profiles-daemon (Arch) with amd-pstate; suspend on idle; suspend-then-hibernate after 2 h | [New] |
| Mirrors | rate-mirrors weekly with safety checks (D-29) | [C] tool, [New] safety |
| Dedup | bees on btrfs, from karchy's fork (`karchy-bees`, D-85), on by default (the installer asks; D-86). `karchy-bees.service` deduplicates the system disk with karchy's options and limits from `/usr/share/karchy/bees.conf` (yours go in `/etc/karchy/bees.conf`): at most one core and only idle CPU, a memory ceiling, a hash table sized from the disk; never rewrites snapper's snapshots, keeps preallocated space, logs no file names, and leaves new data alone until it has been stable for 5 minutes (D-103); AC power only on laptops. | Secure Boot | sbctl + Microsoft keys, signed Limine, config hash enrollment (installer step) | [C] |
| Firmware | fwupd (menu entry) | [O] |
| AUR helper | paru (from `[cachyos]`) | [C] |
| Fonts | JetBrains Mono Nerd; Noto (+ CJK, emoji); Symbols Nerd Font Mono for icons; karchy Symbols for karchy's mark (D-125). ## Shell (Omarchy Quickshell)

Kept:
- **Core:** host, IPC, plugin registry (first-party plugins and add-on packages in `/usr/share/karchy/plugins`, D-106) and `karchy plugin list|enable|disable`, bar engine, `omarchy` router, Commons and Ui, `shell.json`.
- **Services:** notifications (with the hover ✕), OSD, polkit, lock (with the time and date above the password field [New]; turn it off in Settings › Appearance › Lock screen, or `lock.clock: false` in `~/.config/karchy/shell.json`), idle, clipboard history, reminders, theme/background picker, speed tests, and the battery service (only on machines with a battery). `~/.config/karchy/shell.json` holds only what you changed; everything else follows karchy's defaults, also after updates (D-92).
- **Menu:** the engine, used as the launcher (app search). The tree is in `menu.md`.
- **Floating bar** [New]: floats inset from the screen edge and docks on a monitor while a window there is maximized; `bar.style` auto, floating or docked (`karchy bar style`, Settings › Appearance). See `architecture.md`, "The bar: floating and docked".
- **Bar modules:** workspaces, clock (clock and calendar only), notifications (D-112: a bell beside the clock with a dot while notifications wait unseen; its panel is described under Notifications below), tray, audio, microphone, network, Bluetooth, display brightness, power, media, the indicators for kept features (Stay Awake shows only while on, and a click turns it off), and running VMs and containers (each shown only while something runs; D-63). A workspace holding a window that asked for attention is drawn in the urgent colour (D-91).
- **Notifications** [New] (D-112): behaves as Android's notification shade does, in karchy's panel style. A notification pops up unless its app is set to Silent or Off, it came with low urgency, or Do Not Disturb is on. One nobody answered (its popup timed out, or it got none) waits in the bell's panel until it is opened, dismissed or cleared, and keeps its buttons while the app that sent it is still there. The panel lists ongoing ones first (the app marked them `resident`; Clear all leaves them), then the rest, then a Silent section; headers show only when there is more than one section. Several from one app fold under the newest ("3 more from Signal"). ⋯ on a notification (or a right click) sets its app to Allow, Silent or Off (Off asks first) and opens Settings › Notifications at that app, which lists every app that has sent one with the same three choices (`karchy-settings-notifications`, `~/.config/karchy/notifications.json`). History (a link at the bottom) shows the last day's dismissed and answered ones. No snooze, no per-app sound setting, no channels (freedesktop notifications have none).
- **Updates indicator** [New] (D-61): shows while karchy or package updates wait (`karchy-update-check`, a user timer every 6 hours, no root); click opens the Updates window. A new karchy release is also announced once by notification. **Minimized indicator** [New] (D-60): shows while windows are minimized; click brings one back.
- **Updates window** [New] (D-81): what `karchy update` would install, before it runs: Arch news since the last update first, then the karchy release (with its release notes), apps by name, system components (the ones that need a restart first) and AUR packages, and the release channel, switched there after asking. Install runs `karchy update` in the floating terminal, which keeps the password prompt, AUR build review, config merges and the restart question. A Firmware part runs `karchy-update-firmware` in the floating terminal (fwupd; `karchy updates firmware` opens the window there; D-133). Opened by the updates indicator, Update in the menu, Settings › About and `karchy updates`; it reads `karchy-update --plan`.
- **Proposed, needs user approval:** the active-window title module.

Dropped: dock and app grid, emoji picker, intro animations and owe, weather, world clock, AI usage, Tailscale, Dropbox, remote session, dev gallery.

## Agent skills

karchy tells AI coding agents (Claude Code, Codex, Gemini CLI and others) how this system works, so you can ask one to change a setting, add a keybinding or find a fault, and it uses karchy's own commands instead of guessing.

- The skills are `karchy` (customizing and running the system), `karchy-troubleshoot` (logs, crashes, boot problems, bug reports) and one for each of Virtual machines and Containers while that feature is installed. Agents are told to leave the VPN alone; you change it in its panel or in Settings › Network › VPN.
- `~/.agents/skills` is the one skills folder for every agent. Most agents read it themselves. For the ones that don't (Claude Code's `~/.claude/skills`, Antigravity, Kiro), karchy makes their skills folder a link to it, so a skill you put in `~/.agents/skills` reaches every agent. Run `karchy agent skills status` to see the links.
- If an agent's skills folder already exists as a real folder (you used Claude Code before), karchy leaves it and links its own skills into it. `karchy agent skills --adopt` moves what that folder holds into `~/.agents/skills`, overwriting nothing, and makes it the link.
- The skills ask an agent to make a small change (a setting, a keybinding, a theme) directly and tell you how to undo it, and to plan a large one (many packages, `/etc`, services, disks, the VPN) with you and take a snapshot first.
- Your own skills are never replaced or removed. A skill of yours named like one of karchy's wins, and karchy says so.
- If `~/.agents` is your own git repository, karchy adds one `skills/karchy*` line to its `.gitignore` (or to `.git/info/exclude` when it has none), once, and commits nothing. On a new machine, where karchy made `~/.agents` first, bring your repository in with:

  ```sh
  cd ~/.agents
  git init
  git remote add origin <your repository>
  git fetch
  git checkout -t origin/main
  ```

  karchy's links don't collide with your files, so the checkout works in place.
- karchy does not write or link an instructions file (`AGENTS.md`, `CLAUDE.md`). That stays yours.

## Mounts

- **USB:** udisks2 + udiskie automount with a notification [O].
- **Sleep with shares open:** network locations opened in the file manager (gvfs) are disconnected just before sleep, because a file being read from one makes suspend fail; they reconnect when opened again (`karchy-sleep-shares`, D-99). Kept NAS mounts are kernel mounts and are left alone.
- **Screen sharing:** when an app asks to share (a call in the browser, OBS), karchy's menu lists the screens, the windows and "A region…" (`karchy-share-picker`, the picker xdg-desktop-portal-hyprland runs; D-102).
- **Booted a snapshot:** a notification names the snapshot (number, date, what changed) and offers "Restore this snapshot" (`karchy-snapshot-boot`, D-100).
- **Internal data disks:** fstab at `/mnt/<label>`, with `nofail` and `x-gvfs-show`, owned by the user, NTFS via `ntfs3`. The installer sets up existing ones; a notification offers new ones [New]. Built: `karchy-disk-fstab`, `karchy-disks-check`, `karchy-disk-keep`.
- **NAS:** browse via gvfs-smb. Settings › Storage › "Keep a share mounted…" (pick a share open in the file manager, or type `smb://server/share`) writes an fstab systemd automount (`nofail,_netdev,x-systemd.idle-timeout`) with root-only credentials; "Stop keeping" undoes it (D-76, D-133) [New]. Built: `karchy-mount-keep`.

## Install tiers (D-28)

**Always:**
- desktop portals (`xdg-desktop-portal-hyprland` + `-gtk`)
- `systemd-oomd`
- `fstrim.timer`, monthly btrfs scrub, `smartd`; a SMART warning or a scrub that finds errors shows as a desktop notification with the details one click away (`karchy-disk-health`, D-99)
- `paccache` cleanup, `.pacnew` alerts (`pacdiff`)
- the rate-mirrors timer
- a default-apps list: links → Brave Origin, PDF → Brave Origin, images → imv, video and audio → mpv, folders → Thunar, plain text and Markdown → Omawrite
- Thunar archive actions (`thunar-archive-plugin` + xarchiver + `7zip`) and the karchy right-click actions (D-36, D-40)
- `avahi` + `nss-mdns`
- LocalSend, GNOME Disks, Disktree, omacalc, Omawrite, Omasnap; Omarchy's theme path `~/.local/state/omarchy/current` links to karchy's, so the `[omarchy]` apps follow the theme (D-72)
- `xdg-user-dirs` (the home folders, Projects included), with Downloads, Projects, Pictures and Videos bookmarked in the file manager's sidebar at the first login (D-75); `man-db`
- `openssh`, `rsync`, `unzip`
- a check that the desktop draws on the graphics card: Settings › About shows what draws it (`karchy-hw-renderer`, through EGL like every Wayland app), and a login notification warns when it falls back to the processor (llvmpipe), with the likely cause and the fix; its actions are Open Settings and Don't show again, and About can turn the warning back on
- the Wi-Fi regulatory domain, set from the timezone when a Wi-Fi device appears (each boot) and when the timezone is changed in Settings › Date & Time (`iw`, `wireless-regdb`; ported from CachyOS). Without it the kernel stays in the world domain, with no 6 GHz. A `COUNTRY=XX` line in `/etc/karchy/wifi-country` overrides it; Settings › Network › Advanced sets or clears it (`karchy-network-country`).

**Detected at install:**
- CPU microcode (`amd-ucode` or `intel-ucode`).
- **NVIDIA GPU:** the driver follows the GPU generation, read from the PCI device ID in sysfs (`karchy-hw-nvidia-generation`; with several NVIDIA GPUs the newest generation decides):
  - Turing and newer (device ID 0x1e00 and up): `karchy-nvidia`, with `linux-cachyos{,-lts}-nvidia-open` and `nvidia-utils`. The open modules need the GSP firmware these cards have.
  - Maxwell, Pascal and Volta (0x1340 to 0x1dff): `karchy-nvidia-580xx`, with `linux-cachyos{,-lts}-nvidia-580xx` and `nvidia-580xx-utils`, NVIDIA's 580 legacy branch. That driver depends on its 32-bit libraries, so these machines also get `[multilib]` enabled. NVIDIA VA-API uses the direct backend on every generation (the EGL backend has been broken since driver 525).
  - Kepler and older: no NVIDIA driver (NVIDIA's current drivers dropped them; the last was 470). The installer says so, and nouveau drives the card.

  Both packages add `libva-nvidia-driver` and early KMS (NVIDIA's modules in the initramfs). Early KMS breaks resume from hibernation (NVIDIA open-gpu-kernel-modules issue #1343, still open on 620), so both turn hibernation off in `sleep.conf.d` and the lid only suspends (D-78). The installer enables NVIDIA's suspend/resume services only for the 580 driver; from 595 the open driver keeps video memory across suspend itself. `karchy-nvidia-580xx` provides and conflicts with `karchy-nvidia`, so only one is installed and anything that checks for `karchy-nvidia` (such as GPU containers) finds either.
- **Battery:** the shell battery service (a warning at 15% and at 5%, once per discharge and gone when the charger goes in: `battery.low` and `battery.critical` in shell.json or Settings › Power), hibernation at 3% through UPower so an unattended laptop keeps its session (D-93), suspend-then-hibernate, power-profiles-daemon. Automatic timezone is not built yet: `tzupdate` is AUR-only and asks a web service where you are (needs a decision).
- **Framework** (DMI vendor): `framework-system` (`framework_tool`: charge limit, firmware and EC state).
- **Fingerprint reader:** Settings › Security offers "Set up…" under Fingerprint when a reader is found; it enrolls a finger, then adds fprintd to polkit and the lock screen, not sudo (D-14).
- **Firmware in Setup Mode:** the Secure Boot step (D-31).

**Installer choice:** bees dedup, on by default (D-86).

**Optional (Quick install › System features, D-70):**
- Printers & scanners (package `karchy-printing`, D-67): CUPS with Omarchy's hardened cups-browsed (own user, sandboxed, driverless queues only), `system-config-printer`, `sane`, `sane-airscan`, `simple-scan`, and `ipp-usb` for driverless USB printers and scanners (D-38).
- Containers (package `karchy-containers`, D-67): rootless Podman (`podman`, `crun`, `netavark`, `aardvark-dns`, `passt`), `podman-docker` for the `docker` command, `docker-compose` against the user's Podman socket (`DOCKER_HOST` via `/usr/lib/environment.d`, the socket enabled for every user by the package), and `nvidia-container-toolkit` with karchy-nvidia; the Containers panel and window (D-63).
- Virtual machines: `qemu-desktop`, `edk2-ovmf`, `swtpm`, `spice-gtk`; `karchy vm`, VMs in `~/VMs` (no copy-on-write), no libvirt; the VMs panel and window (D-63).
- Home backup to the NAS (phase 7).
