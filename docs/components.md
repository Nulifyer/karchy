# Components

What a karchy install contains. Tags: [O] Omarchy does it, [C] CachyOS does it, [New] neither does. Packages come from Arch unless a repo is named. Anything not listed here is not in the base install.

### Window modes (D-159)

A workspace tiles or floats (Settings › Appearance › Workspace layout sets the default for new workspaces). The two modes share one rule for which window is in front and one Alt+Tab (D-159, D-165).

**Tiling**

- App windows share the workspace and never overlap.
- A floating window is drawn in front of every tiled one, and nothing can put a tiled window in front of it. So only a window you deal with and close floats here: a dialog, a file chooser, karchy's floating terminal, About, the calculator. A window you keep open and switch to tiles, the image viewer, the video player and the document viewer among them (D-165). karchy's own windows (Settings, Quick install, Updates, Virtual machines, Containers) float too (D-114).
- Among the floating windows, the one with the keyboard is in front, whether a click, Alt+Tab or a command gave it the keyboard. Focus follows the pointer here, and focus that only followed the pointer raises nothing.
- Super+T floats one window, or tiles it again.

**Floating (as on Windows)**

- Every app window floats, with a titlebar: drag it to move, double-click it or □ to maximize, − to minimize, × to close, drag an edge to resize. Windows open at a comfortable size, each stepped from the last.
- A click gives a window the keyboard and brings it to the front; the pointer alone does neither. A window given the keyboard any other way comes to the front too: Alt+Tab, a launcher that finds it open, an app that asks for focus, the window in front closing.
- A maximized window is in front when it has the keyboard, and the other windows wait behind it; one of them given the keyboard comes in front of it again. It stays maximized when another window opens: an app window, a dialog or one of karchy's own opens in front of it, at its own size (D-165). One window on a workspace is maximized at a time, which is Hyprland's rule: maximizing a second brings the first back to its own size.
- Super+Left and Super+Right put a window on the left or right half of its monitor (D-165). A half is the tile two windows would share on a tiling workspace: the same gaps to the screen edge, the bar and the other half, with the titlebar on top.
  - The arrow the other way brings the window back to the place and size it had before; one more press puts it on that half.
  - The same arrow again sends it on to the next monitor that way, onto the half it enters by, and does nothing where there is no monitor. On a monitor whose workspace tiles, the window tiles.
  - Super+Up maximizes a window on a half, and Super+Down brings it back to the half. Super+Down on a half gives the earlier place and size back; only a window on no half is minimized.
  - A window dragged off its half keeps the half's size: Hyprland tells karchy nothing about a drag, so the size cannot come back as the drag starts, as it does on Windows. Super+Down, or snapping it again and back, gives the earlier size back where the window now is. A window resized by hand keeps the size it was given.
  - A maximized window goes straight to the half the arrow points at, also one that was maximized from the other half. A dialog, a pinned window and a fullscreen window are left alone.
  - The bar docks while a window on its monitor is maximized and floats again afterwards, which moves the top of a half by the bar's margin. A window on a half follows it, a moment after a window enters or leaves maximized.
- A dialog keeps the size its app gave it and stays in front of its app's windows. The portal's file chooser stays in front of every window on its workspace until it is answered.
- Nothing else stays on top. karchy's own windows and its floating terminal go behind the window you click, like any other.

**Both**

- Alt+Tab goes to the window used before this one, and further back while Alt is held ([keybindings.md](keybindings.md)); the next part says how.
- Asking for one of karchy's windows while it is open (Super+K, the menu, `karchy settings`) brings it to the front, from another workspace too.
- Picture-in-picture and the webcam overlay are pinned: in front of everything, on every workspace.

Which kind a window is:

| Window | Kind | Tiling | Floating |
|---|---|---|---|
| An app's own window, a terminal, a browser, imv, mpv, Evince | app window | tiles | floats, stacks by use |
| A dialog (it has a parent window, or cannot be resized): confirmations, Preferences, a toolkit's own file chooser | dialog | floats | own size, in front of its app |
| The portal's file chooser and permission prompts (`xdg-desktop-portal-gtk`) | dialog of another app | floats | in front of every window, tag `stay-in-front` |
| karchy's floating terminal (`org.karchy.terminal`), About, `TUI.float`, btop, the calculator, the captive portal sign-in, LocalSend | short-lived | floats | floats, stacks by use |

| Steam | app window that Omarchy floats | floats | floats at its own size, stacks by use |
| Picture-in-picture, the webcam overlay | overlay | pinned | pinned |
| The password prompt (polkit), the menu, notifications, the lock screen | not windows: shell layers above all windows | | |

**Alt+Tab and the switcher (D-165)**

- Tab with Alt held picks a window, and letting go of Alt goes to it. Nothing changes before that: the windows passed on the way are never given the keyboard, so they keep their place in front of or behind the others and their place in the order. The window you left is then the one used before the new one, and one more Alt+Tab goes back to it.
- The windows of a walk are the ones on the workspace, last used first, then the ones minimized from this workspace, which is where Windows puts a minimized window. Stopping on a minimized window brings it back to the workspace, with the keyboard and in front (`karchy-hyprland-window-restore`). A window minimized from another workspace is not in the walk; the bar's indicator and Super+Shift+M reach it.
- The switcher shows the walk: each window's icon and title in the walk's order, the target marked, a minimized window dimmed with the minimized mark. It appears once Alt has been held for 150 ms after the first Tab, or at the second Tab, so a quick Alt+Tab switches with nothing drawn. It takes neither the keyboard nor the pointer. The icon is the app's own, from its desktop entry or the icon theme; an app without one gets its first letter.
- Alt+Escape gives the walk up and stays on the window you were on. A click, a window that opens or asks for the keyboard, and a change of workspace end it the same way. A window that closes during the walk leaves it.
- The walk is kept in one place, `default/hypr/window-switch.lua`, in Hyprland. It sends every change as one event on Hyprland's event socket (`custom>>karchy-window-switch show <place of the target> <address> <address>* …`, a star for minimized, and `… hide`), and the shell plugin `shell/plugins/window-switcher` draws what the last event said and decides nothing. So the picture cannot name one window while the keys go to another, and with the plugin off or the shell not running Alt+Tab works the same, unseen.
- Run without a modifier held (`hyprctl dispatch`, or a key of your own without one), the action switches at once, since nothing would be let go to end a walk.

A window rule keeps a window of your own in front of the others on its workspace: `o.window("its-class", { float = true, tag = "+stay-in-front" })`. The code is `default/hypr/stacking.lua`, `default/hypr/window-switch.lua`, `default/hypr/snap.lua` and `default/hypr/workspace-modes.lua`; it runs on Hyprland's focus and open events and on the keys.

## Shell (Omarchy Quickshell)

Kept:
- **Core:** host, IPC, plugin registry (first-party plugins and add-on packages in `/usr/share/karchy/plugins`, D-106) and `karchy plugin list|enable|disable`, bar engine, `omarchy` router, Commons and Ui, `shell.json`.
- **Services:** notifications (with the hover ✕), OSD, polkit, lock (with the time and date above the password field [New]; turn it off in Settings › Appearance › Lock screen, or `lock.clock: false` in `~/.config/karchy/shell.json`), idle, the clipboard (below), reminders, theme/background picker, speed tests, and the battery service (only on machines with a battery). `~/.config/karchy/shell.json` holds only what you changed; everything else follows karchy's defaults, also after updates (D-92).
- **Menu:** the engine, used as the launcher (app search). The tree is in `menu.md`.
- **Floating bar** [New]: floats inset from the screen edge and docks on a monitor while a window there is maximized; `bar.style` auto, floating or docked (`karchy bar style`, Settings › Appearance). See `architecture.md`, "The bar: floating and docked".
- **Bar modules:** workspaces, clock (clock and calendar only), notifications (D-112: a bell beside the clock with a dot while notifications wait unseen; its panel is described under Notifications below), tray, audio, microphone, network, Bluetooth, display brightness, power, media, the clipboard (in the tray's drawer, the part of the bar that opens on hover; D-167), the indicators for kept features (Stay Awake shows only while on, and a click turns it off), and running VMs and containers (each shown only while something runs; D-63). A workspace holding a window that asked for attention is drawn in the urgent colour (D-91).
- **Clipboard** [New] (D-167): works as on Windows. Ctrl+C, Ctrl+X and Ctrl+V are the apps' own; in a terminal copy and paste are Ctrl+Shift+C and Ctrl+Shift+V, because Ctrl+C interrupts.
  - **A copy is held.** `karchy-clipboard-persist.service` (wl-clip-persist) keeps what was copied pasteable after the app that copied closes, every format of it, up to 64 MiB.
  - **The history** (Super+Ctrl+V, as Win+V) lists what was copied, newest first: text, images, and a file manager's file copies. Choosing an entry puts it back on the clipboard and pastes it where the cursor is, with the focused window's own paste keys (Ctrl+V, or Ctrl+Shift+V in a terminal). An entry can be pinned, deleted, or opened in its app; Clear all removes everything that is not pinned. Its keys are in `keybindings.md`.
  - **The bar panel** shows the pinned entries and the five newest others, with the same paste, pin, delete and Clear all, the "Keep a history" switch, and a button to the full history.
  - **What is kept, and where.** The 100 newest entries, 64 MiB in all, none larger than 16 MiB; a larger copy still pastes, it is only not listed. They live in memory (`$XDG_RUNTIME_DIR/karchy/clipboard`, this user only) and are gone at logout, restart or power-off, as on Windows. A pinned entry moves to `~/.local/state/karchy/clipboard` and stays until it is unpinned or deleted. Nothing that is not pinned is written to disk.
  - **What is never kept.** A password manager's copy (one carrying `x-kde-passwordManagerHint`, as KeePassXC and other managers that mark their copies send): the history skips it and the persist service leaves it to its app, which clears it after its own delay. The mouse selection (select, then middle click) is separate from the clipboard, as on every Linux desktop: it is not recorded, not held, and Ctrl+V never pastes it.
  - **Formatting** is not kept: an entry pasted from the history is plain text, an image or files. The copy itself, pasted with Ctrl+V, keeps every format.
  - **Forgetting.** Deleting the entry that is on the clipboard, and Clear all, empty the clipboard too, so what was removed can't be pasted. "Keep a history" in the bar panel (`clipboard.history` in `shell.json`) turns the recording off: nothing more is recorded and what is not pinned is forgotten, while copy and paste go on working. A password copied from something that doesn't mark it (a web page, a browser extension) is recorded like any text; delete it, or it leaves with the session.
  - The lock screen covers the history and the panel, and their keys do nothing while it is up. `karchy plugin disable karchy.clipboard` only takes the icon off the bar.
- **Notifications** [New] (D-112): behaves as Android's notification shade does, in karchy's panel style. A notification pops up unless its app is set to Silent or Off, it came with low urgency, or Do Not Disturb is on. One nobody answered (its popup timed out, or it got none) waits in the bell's panel until it is opened, dismissed or cleared, and keeps its buttons while the app that sent it is still there. The panel lists ongoing ones first (the app marked them `resident`; Clear all leaves them), then the rest, then a Silent section; headers show only when there is more than one section. Several from one app fold under the newest ("3 more from Signal"). ⋯ on a notification (or a right click) sets its app to Allow, Silent or Off (Off asks first) and opens Settings › Notifications at that app, which lists every app that has sent one with the same three choices (`karchy-settings-notifications`, `~/.config/karchy/notifications.json`). History (a link at the bottom) shows the last day's dismissed and answered ones. No snooze, no per-app sound setting, no channels (freedesktop notifications have none).
- **Updates indicator** [New] (D-61): shows while karchy or package updates wait (`karchy-update-check`, a user timer every 6 hours, no root); click opens the Updates window. A new karchy release is also announced once by notification. **Minimized indicator** [New] (D-60): shows while windows are minimized; click brings one back.
- **Window switcher** [New] (D-165): the windows of an Alt+Tab while Alt is held, minimized ones included; see [Window modes](#window-modes-d-159). `karchy plugin disable karchy.window-switcher` turns the picture off and leaves the keys.
- **Updates window** [New] (D-81): what `karchy update` would install, before it runs: Arch news since the last update first, then the karchy release (with its release notes), apps by name, system components (the ones that need a restart first) and AUR packages, and the release channel, switched there after asking. Install runs `karchy update` in the floating terminal, which keeps the password prompt, AUR build review, config merges and the restart question. A Firmware part runs `karchy-update-firmware` in the floating terminal (fwupd; `karchy updates firmware` opens the window there; D-133). Opened by the updates indicator, Update in the menu, Settings › About and `karchy updates`; it reads `karchy-update --plan`.
- **Proposed, needs user approval:** the active-window title module.

Dropped: dock and app grid, emoji picker, intro animations and owe, weather, world clock, AI usage, Tailscale, Dropbox, remote session, dev gallery.

## Agent skills

karchy tells AI coding agents (Claude Code, Codex, Gemini CLI and others) how this system works, so you can ask one to change a setting, add a keybinding or find a fault, and it uses karchy's own commands instead of guessing.

- The skills are `karchy` (customizing and running the system), `karchy-troubleshoot` (logs, crashes, boot problems, bug reports) and one each for Virtual machines, the Containers app and karchy's Podman setup while that one is installed. Agents are told to leave the VPN alone; you change it in its panel or in Settings › Network › VPN.
- `~/.agents/skills` is the one real skills folder, and every skill is managed there. Most agents read it themselves. For the ones that don't (Claude Code's `~/.claude/skills`, Antigravity, Kiro), karchy makes their skills folder a link to it, so a skill you put in `~/.agents/skills` reaches every agent. Run `karchy agent skills status` to see the links.
- If one of those folders is already a real folder (you used Claude Code before), `karchy update` brings it in: what it holds moves into `~/.agents/skills`, and the folder becomes the link. The update says what moved. Nothing is overwritten or deleted. If a skill of the same name is already in `~/.agents/skills` and differs, both are kept: the agent's copy goes to `~/.agents/skill-clashes/<agent>/`. A folder on another filesystem, or one that is a link to somewhere else, is left as it is, and karchy says so. `karchy agent skills keep ~/.claude/skills` gives the folder back what was moved and keeps it a folder of its own; `karchy agent skills share ~/.claude/skills` brings it in again.
- The skills ask an agent to make a small change (a setting, a keybinding, a theme) directly and tell you how to undo it, and to plan a large one (many packages, `/etc`, services, disks, the VPN) with you and take a snapshot first.
- Your own skills are never replaced or removed. A skill of yours named like one of karchy's wins, and karchy says so.
- If `~/.agents` is your own git repository, karchy adds one `skills/karchy*` line to its `.gitignore` (or to `.git/info/exclude` when it has none), once, and commits nothing. What an agent's folder brought in (Claude Code's `synced/` and `.trash/` too) shows there as new files, for you to commit or ignore. On a new machine, where karchy made `~/.agents` first, bring your repository in with:

  ```sh
  cd ~/.agents
  git init
  git remote add origin <your repository>
  git fetch
  git checkout -t origin/main
  ```

  karchy's links don't collide with your files, so the checkout works in place.
- karchy does not write or link an instructions file (`AGENTS.md`, `CLAUDE.md`). That stays yours.

## Mounts

- **USB:** udisks2 + udiskie automount with a notification [O].
- **Sleep with shares open:** network locations opened in the file manager (gvfs) are disconnected just before sleep, because a file being read from one makes suspend fail; they reconnect when opened again (`karchy-sleep-shares`, D-99). Kept NAS mounts are kernel mounts and are left alone.
- **Screen sharing:** when an app asks to share (a call in the browser, OBS), karchy's menu lists the screens, the windows and "A region…" (`karchy-share-picker`, the picker xdg-desktop-portal-hyprland runs; D-102).
- **Booted a snapshot:** a notification names the snapshot (number, date, what changed) and offers "Restore this snapshot" (`karchy-snapshot-boot`, D-100).
- **Internal data disks:** fstab at `/mnt/<label>`, with `nofail` and `x-gvfs-show`, owned by the user, NTFS via `ntfs3`. The installer sets up existing ones; a notification offers new ones [New]. Built: `karchy-disk-fstab`, `karchy-disks-check`, `karchy-disk-keep`.
- **NAS:** browse via gvfs-smb. Settings › Storage › "Keep a share mounted…" (pick a share open in the file manager, or type `smb://server/share`) writes an fstab systemd automount (`nofail,_netdev,x-systemd.idle-timeout`) with root-only credentials; "Stop keeping" undoes it (D-76, D-133) [New]. Built: `karchy-mount-keep`.

## Install tiers (D-28)

**Always:**
- desktop portals (`xdg-desktop-portal-hyprland` + `-gtk`)
- `systemd-oomd`
- `fstrim.timer`, monthly btrfs scrub, `smartd`; a SMART warning or a scrub that finds errors shows as a desktop notification with the details one click away (`karchy-disk-health`, D-99)
- `paccache` cleanup, `.pacnew` alerts (`pacdiff`)
- the rate-mirrors timer
- a default-apps list: links → Brave Origin, PDF → Brave Origin, images → imv, video and audio → mpv, folders → Thunar, plain text and Markdown → Omawrite
- Thunar archive actions (`thunar-archive-plugin` + xarchiver + `7zip`) and the karchy right-click actions (D-36, D-40)
- `avahi` + `nss-mdns`
- LocalSend, GNOME Disks, Disktree, omacalc, Omawrite, Omasnap; Omarchy's theme path `~/.local/state/omarchy/current` links to karchy's, so the `[omarchy]` apps follow the theme (D-72)
- `xdg-user-dirs` (the home folders, Projects included), with Downloads, Projects, Pictures and Videos bookmarked in the file manager's sidebar at the first login (D-75); `man-db`
- `openssh`, `rsync`, `unzip`
- a check that the desktop draws on the graphics card: Settings › About shows what draws it (`karchy-hw-renderer`, through EGL like every Wayland app), and a login notification warns when it falls back to the processor (llvmpipe), with the likely cause and the fix; its actions are Open Settings and Don't show again, and About can turn the warning back on
- the Wi-Fi regulatory domain, set from the timezone when a Wi-Fi device appears (each boot) and when the timezone is changed in Settings › Date & Time (`iw`, `wireless-regdb`; ported from CachyOS). Without it the kernel stays in the world domain, with no 6 GHz. A `COUNTRY=XX` line in `/etc/karchy/wifi-country` overrides it; Settings › Network › Advanced sets or clears it (`karchy-network-country`).

**Detected at install:**
- CPU microcode (`amd-ucode` or `intel-ucode`).
- **NVIDIA GPU:** the driver follows the GPU generation, read from the PCI device ID in sysfs (`karchy-hw-nvidia-generation`; with several NVIDIA GPUs the newest generation decides):
  - Turing and newer (device ID 0x1e00 and up): `karchy-nvidia`, with `linux-cachyos{,-lts}-nvidia-open` and `nvidia-utils`. The open modules need the GSP firmware these cards have.
  - Maxwell, Pascal and Volta (0x1340 to 0x1dff): `karchy-nvidia-580xx`, with `linux-cachyos{,-lts}-nvidia-580xx` and `nvidia-580xx-utils`, NVIDIA's 580 legacy branch. That driver depends on its 32-bit libraries, so these machines also get `[multilib]` enabled. NVIDIA VA-API uses the direct backend on every generation (the EGL backend has been broken since driver 525).
  - Kepler and older: no NVIDIA driver (NVIDIA's current drivers dropped them; the last was 470). The installer says so, and nouveau drives the card.

  Both packages add `libva-nvidia-driver` and early KMS (NVIDIA's modules in the initramfs). Early KMS breaks resume from hibernation (NVIDIA open-gpu-kernel-modules issue #1343, still open on 620), so both turn hibernation off in `sleep.conf.d` and the lid only suspends (D-78). The installer enables NVIDIA's suspend/resume services only for the 580 driver; from 595 the open driver keeps video memory across suspend itself. `karchy-nvidia-580xx` provides and conflicts with `karchy-nvidia`, so only one is installed and anything that checks for `karchy-nvidia` (such as GPU containers) finds either.
- **Battery:** the shell battery service (a warning at 15% and at 5%, once per discharge and gone when the charger goes in: `battery.low` and `battery.critical` in shell.json or Settings › Power; Power saver from the first warning until the charger goes in unless `battery.saver` is off, D-160, D-162), the power source's own power profile and screen brightness when the charger goes in or out (`karchy-power-source`), hibernation at 3% through UPower so an unattended laptop keeps its session (D-93; the level and "hibernate or shut down" are choices in Settings › Power, D-162), suspend-then-hibernate, power-profiles-daemon. Automatic timezone is not built yet: `tzupdate` is AUR-only and asks a web service where you are (needs a decision).
- **Virtual machine** (`systemd-detect-virt --vm`): `karchy-vm`, the SPICE agent (shared clipboard) and the QEMU guest agent (clean shutdown and freeze from the host), both started by udev when their virtio port exists. The display follows the viewer's window (D-174): when virt-manager's, remote-viewer's or QEMU's window changes size, the virtual GPU (virtio-gpu or QXL) announces a new preferred mode and the kernel sends a DRM hotplug event, which Hyprland ignores (it reads a connected output's modes once). A watcher started with the session (`/usr/lib/karchy-vm/display-watch`, `udevadm monitor`, no polling) waits until the sizes stop for half a second and has karchy's Hyprland drop-in (`hypr.d/50-karchy-vm-display.lua`) set the new size on each `Virtual-N` output whose rule asks for `preferred`; a reload keeps it. A size set by hand in Settings › Displays or `~/.config/hypr/monitors.lua` wins over the viewer, and the rule's scale is kept (a number is kept exactly, trimming the size by a few pixels if the scale needs it; `auto` is worked out from the display's current EDID, 1 without one). Not on real hardware: both parts check `systemd-detect-virt` themselves.
- **Framework** (DMI vendor): `framework-system` (`framework_tool`: charge limit, firmware and EC state).
- **Fingerprint reader:** Settings › Security offers "Set up…" under Fingerprint when a reader is found; it enrolls a finger, then adds fprintd to polkit and the lock screen, not sudo (D-14).
- **Firmware in Setup Mode:** the Secure Boot step (D-31).

**Installer choice:** bees dedup, on by default (D-86).

**Optional (Quick install › System, D-70):**
- Printers & scanners (package `karchy-printing`, D-67): CUPS with Omarchy's hardened cups-browsed (own user, sandboxed, driverless queues only), `system-config-printer`, `sane`, `sane-airscan`, `simple-scan`, and `ipp-usb` for driverless USB printers and scanners (D-38).
- Podman (package `karchy-podman`, D-67, D-164): rootless Podman (`podman`, `crun`, `netavark`, `aardvark-dns`, `passt`), `podman-docker` for the `docker` command, `docker-compose` against the user's Podman socket (`DOCKER_HOST` via `/usr/lib/environment.d`, the socket enabled for every user by the package), and `nvidia-container-toolkit` with karchy-nvidia. Docker itself is the entry beside it; the two can't be installed together (`podman-docker` conflicts with `docker`), and Quick install says which one is in the way.

**karchy's own apps (Quick install › karchy, D-164):**
- Containers (package `karchy-containers-app`): the Containers window as an app in the launcher, and its agent skill. It depends on no container engine and works with Podman or Docker, whichever is installed: with neither the window says so and opens Quick install at the two; with both it shows Podman's containers and says why (Podman needs no service running). The bar icon and panel (D-63) are part of karchy and show while containers run.
- Virtual machines: `qemu-desktop`, `edk2-ovmf`, `swtpm`, `spice-gtk`; `karchy vm`, VMs in `~/VMs` (no copy-on-write), no libvirt; the VMs panel and window (D-63). QEMU comes with the app: karchy runs no other kind of VM.
