# Architecture

Status: **proposed for phase 1**. Needs the user's approval; the open questions are at the end. It is based on Omarchy `v4.5.0` (`ac2690cd7`), read at `/home/nulifyer/Projects/Omarchy/reference/omarchy-v4.5.0`.

## Repository layout

The repository root is `$OMARCHY_PATH` on an installed machine, a git checkout at `~/.local/share/karchy`. Omarchy's code reads its own files from `$OMARCHY_PATH/<upstream path>` (its rule: "rely on `$OMARCHY_PATH`"). So vendored files keep their upstream paths, and karchy's own files live in clearly separate places.

```
karchy/
├── bin/                      vendored omarchy-* (subset) + karchy-* (ours)
├── shell/                    vendored Quickshell shell, dropped plugins left out
├── themes/                   our themes only (nulifyer); Omarchy's 23 are fetched (see Themes)
├── default/                  vendored defaults (hypr modules, themed templates, fonts, omarchy/*)
├── karchy/                   karchy's default layer (ours)
│   ├── hypr/                 init.lua, bindings.lua, autostart.lua, qconsole.lua
│   ├── menu.jsonc            the karchy menu tree (docs/menu.md)
│   ├── shell.json            default bar layout and plugin list
│   ├── themed/               gtk.css.tpl, fish prompt template
│   └── thunar/               karchy actions merged into uca.xml
├── config/                   stubs copied once into ~/.config (never overwritten)
├── system/                   files the setup installs under /etc (sudoers, sysctl, greetd, ufw, zswap, tmp.mount…)
├── install/                  installer form, disk step, setup steps, package lists
├── migrations/               karchy's own migrations
├── tools/                    vendor-sync, vm, check scripts
├── vendor/omarchy.lock       upstream tag/commit + every vendored path with its upstream blob hash
├── docs/  .agents/
```

## Vendoring and sync

- `vendor/omarchy.lock` records the upstream tag and commit, and every vendored file with its upstream blob hash. Files karchy replaces are marked `override`.
- `tools/vendor-sync <tag>` fetches the tag into a cache outside the repo. For each locked path:
  - **unchanged locally:** update it to the new upstream version;
  - **`override`:** show the upstream diff (old tag → new tag) so we can merge it by hand;
  - **new upstream files under a vendored directory:** list them; nothing is added automatically.
- It writes a report and never commits. The result goes through a branch and PR like any other change.

Vendored is about 3 MB.
- **Hyprland (`default/hypr/`):** `bootstrap`, `helpers`, `require_optional`, `require_all`, `paths`, `monitor-workspaces`, `envs`, `looknfeel`, `input`, `keyboard`, `windows`, `pop`, `glass`, `nvidia`, `workspace-layouts`, `workspace-modes`, `toggles`, `startup-cursor`, `disabled-input-device`, `apps/`. Not vendored: `omarchy.lua` (it loads everything), `autostart.lua`, `bindings/`, `qconsole.lua` and `dictation-backend.lua`. karchy replaces those (see Seams).
- **Templates:** `default/themed/*.tpl` in full (152 KB). Templates for apps that aren't installed render harmlessly.
- **Commands:** **about 216 of Omarchy's 560**: 205 found by tracing what the kept shell parts, Hyprland modules, menu entries and keybindings call, plus 11 per-app theme and restart commands that `theme-set` calls (they exit early when their app is absent). The list is in the appendix and is generated by `tools/vendor-sync --closure`.
- **Other:** `default/fonts/` (the icon font), `default/omarchy/shortcuts`, `default/omarchy/launcher.hides`, `applications/` (the subset for kept features).

## Themes

Omarchy's 23 themes are 161 MB, mostly wallpapers (up to 24 MB per theme). Committing them would make every upstream sync grow karchy's git history. Proposal: `karchy update` fetches `themes/` from the locked upstream tag into `~/.local/share/karchy/vendor/themes`, and a `themes/` lookup includes both that folder and karchy's own `themes/` (nulifyer). The alternative is to commit them, or use Git LFS (see question Q2).

## karchy's Hyprland composition

`~/.config/hypr/hyprland.lua` (a stub, created once):

```lua
dofile(os.getenv("OMARCHY_PATH") .. "/default/hypr/bootstrap.lua")
require("karchy.hypr.init")    -- karchy's pick of default.hypr modules + bindings + autostart
require("hypr.monitors")        -- user layer (dotfiles)
require("hypr.input")
require("hypr.bindings")
require("hypr.looknfeel")
require("hypr.autostart")
require("default.hypr.toggles")
```

`karchy/hypr/init.lua` requires the vendored modules listed above in Omarchy's order, then `karchy.hypr.bindings` (exactly `docs/keybindings.md`) and `karchy.hypr.autostart`. That autostart runs the shell, the monitor watcher, udiskie and power profiles. It leaves out herdr and Omarchy's first-run provisioning. No vendored file is edited.

## Installer

The **form** is a gum TUI in Omarchy's style (D-08), run from the stock Arch ISO. It asks for: disk (with typed confirmation), keyboard, username, one password, name and email, hostname, timezone, and bees (off by default). Secure Boot is detected automatically.

**Disk and base: change from D-08 proposed.** archinstall 4.5 replaces `systemd`/`sd-encrypt` with udev/busybox `encrypt` unless the disk uses a hardware security key (`archinstall/lib/installer.py:125`), and its only swap option is zram. Both conflict with D-12 and D-10. Proposal: karchy's own `install/disk.sh` + `install/base.sh`:

1. `sgdisk`: 4 GiB ESP plus a LUKS partition.
2. `cryptsetup luksFormat --type luks2`.
3. `mkfs.btrfs` and the D-09 subvolumes.
4. Mount with `zstd:1,noatime`.
5. Swap file on `@swap` via `btrfs filesystem mkswapfile`.
6. `pacstrap` the base list.
7. fstab, locale, user, mkinitcpio `HOOKS` with `systemd … sd-encrypt`.
8. Limine + limine-entry-tool + limine-snapper-sync, with `rd.luks.name=` on the kernel command line.

That's about 300 lines of bash, with each step logged and safe to retry. The alternative is archinstall followed by a rewrite of the hooks and swap (question Q1).

**Setup** (`install/setup.sh`, also re-run by `karchy update` for new steps):

1. Repos: `[omarchy]` and `[cachyos]` added after Arch's, with keyrings.
2. Packages: the Always tier plus the Detected tier.
3. `/etc` files from `system/`.
4. Services: greetd auto-login, NetworkManager, resolved, ufw, bluetooth, fstrim, scrub, smartd, paccache, oomd, power-profiles-daemon (laptop).
5. The karchy checkout into `~/.local/share/karchy`.
6. User stubs into `~/.config` (only where missing).
7. Plugins via `omarchy plugin add`.
8. Default theme nulifyer.
9. Snapper config.

## VM (`tools/vm`)

- `tools/vm fetch` downloads the current Arch ISO and checks its signature.
- `tools/vm new` creates a 40 GiB qcow2 disk and UEFI variables (OVMF; the Secure Boot firmware with `--secureboot`).
- `tools/vm run` starts it with `qemu-system-x86_64 -enable-kvm`, `virtio-vga-gl` with `gl=on`, 4 vCPUs and 8 GiB RAM, and the karchy repo shared read-only through virtiofs, so the installer can run from the local branch without a push.
- `tools/vm snap` and `restore` use qcow2 snapshots for quick retries.

Host check: `qemu-desktop` 11.1.3, libvirt, `edk2-ovmf` (including `OVMF_CODE.secboot.4m.fd`), swtpm and `/dev/kvm` are present.

## Open questions

- **Q1. Disk and base:** karchy's own pacstrap scripts (recommended) or archinstall plus a hooks and swap rewrite?
- **Q2. Themes:** fetch them at update time (recommended), commit them, or Git LFS?
- **Q3. Command names:** vendored commands stay `omarchy-*`. karchy's own are `karchy-*`, with a small `karchy` router for `karchy update` and `karchy vm …`. The `omarchy` router stays for `omarchy plugin` and `omarchy bar`. Acceptable?
- **Q4. DNS switch** in the network panel: keep Omarchy's DNS presets (Cloudflare, Google, DHCP) with their NOPASSWD rule, or remove that section?
- **Q5. Dotfiles checkout location** (phase 2): `~/.local/share/karchy-user` or `~/Projects/dotfiles`?
